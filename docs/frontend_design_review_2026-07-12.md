# openmc2donjon Web Frontend — Design Review Synthesis

Answering the owner's three questions directly: **用户友好吗** — the working cores are excellent, but the app repeats itself between them (the same next-step link set renders up to five times after one convert). **需要这么多东西吗** — every route earns its existence; roughly a third of the *sections* do not. **流程合理吗** — the J1 spine is genuinely minimal (1 typed path, ~6 clicks to a runnable rdonjon command), but the product's own destination, DONJON, is missing from the nav, the homepage, and every pipeline model the UI draws. The fix everywhere is subtraction and re-labeling, never new features.

## 2. Target information architecture

**Primary nav (4):** `Convert | OpenMC prep | Inspect HDF5 | DONJON`
**More (5):** `Commands, Command builder, ADF/SPH sidecars, PyGan validation, Settings` (the separate "Bundle" row is dropped — bundle is a step reached from convert results and the builder index, not a destination).

- **`/`** — Triage which lane fits, show backend health and the accepted-validation credential; all six jobs reachable from the first screen.
- **`/convert`** — Turn an existing MGXS HDF5 into checked L_MULTICOMPO/L_MACROLIB ASCII (J1); production checks on by default.
- **`/openmc`** — Plan the OpenMC-side commands that produce the MGXS HDF5 and, when chosen, the CE/MG SPH evidence (J2+J3 planning); nav lands on export planning (`?workflow=two-step&production=1`, dropping only `equivalence=sph` — plain `/openmc` would silently disable production gates).
- **`/inspect`** — Read and verify any MGXS HDF5 down to per-mixture cross sections and scatter moments (J4), with exits to Convert and diff.
- **`/donjon`** — Generate the editable deck skeleton and run commands that consume the ASCII output (J5); nav description: "Generate the DONJON deck that consumes your ASCII."
- **`/equivalence`** — Build the five sidecar make/augment commands with mode-shaped forms (J3 decision surface).
- **`/builder`** — Fill inputs, copy the exact CLI for the 14 auxiliary commands (J3 prep, J5 packaging, J6); bare URL lands on a command index, not a silent diff form.
- **`/commands` (+`[id]`)** — Advanced reference: what each CLI command is for, its status, and where it runs on the web.
- **`/pygan`** — Optionally prove the ASCII and PyGan writers agree (J6).
- **`/settings`** — Default path prefix for path inputs and the file browser (nav description says exactly that).

## 3. Highest-leverage flow changes (ordered)

**1. Put DONJON at the end of every model of the flow.** Today the tagline is "for DONJON" yet the primary success card, the 5-stage delivery checklist, the home page, and the nav all terminate at Bundle or earlier; the one visible post-convert DONJON button sits mid-page in a rival card, and following it triggers an amber "manifest not found" warning for an optional step the user never took. Change: DONJON as 4th primary nav item; home "After you convert" block (DONJON + Bundle, replacing "Advanced tools"); a 6th terminal "DONJON" stage on the delivery checklist; gate the `manifest=` param in `convertDonjonGuideHref` on the existing probe result (or render a 404 as a neutral note). Cost: navigation.ts, one checklist item, one href guard — near zero.

**2. Collapse /convert's post-run report to two disjoint cards.** Two adversarial defenses pulled in opposite directions (merge everything into the outcome card vs. keep two cards); the reconciliation that honors both: card 1 (ConvertOutcomeSummary) = verdict + "Why this state" + Preview ASCII + Copy CLI only; card 2 (OutputActions, retitled **"Deliver to DONJON"**) = DONJON guide first, Bundle with the fork stated once ("The DONJON guide works from the ASCII path directly; bundle for the manifest-backed record"), file-status probe + Refresh + conflict badge. Zero overlapping buttons, page order verdict→gates→SPH→delivery preserved. Also delete: Gate highlights (gates render once in CheckCards, which auto-open on failure), ResultOverview, one of the two delivery-checklist renderings, the second BundleManifestProbe mount, the 01/02/03 stepper, the dead `canConvertNow` branch, and the intent banner for both `generic` and `direct-convert` intents. Render `convertPostWriteFocus`'s title/body (currently 90% dead code) as the station headline with DONJON as the default-branch primary. Cost: pure subtraction; roughly two viewports instead of seven, no substance lost.

**3. Make the production contract the default, not a query param.** Today `production` defaults to false and the strict preset survives only in 60-char curated URLs; two in-app links ("Open converter" on /pygan, "Back to convert" on /donjon) silently downgrade it, as does any bookmark. Change: `production=true` as the form default (URL params override for demo/SPH deep links), strip check/production from curated hrefs, and replace the four-checkbox row with a "Checks: Production / Standard / None" segmented control (the code already computes exactly this enum for its badge), nesting "Known mesh required" under it and moving "Overwrite" beside the Convert button. Cost: a form refactor plus tests; removes a silent safety downgrade and three fake decisions from the 90% path.

**4. Give /inspect and the ASCII preview exits.** /inspect emits zero outbound links although the whole app funnels into it, and the preview anchor strands users at page bottom below every next-step surface. Change: on inspection OK, one "Convert this HDF5" button (prefilled `?input=`, macrolib when SPH present) and a "Diff against a reference" link (`?command=diff&candidate_h5=`); on FAIL, keep the dead end (correct). End AsciiPreview with "Looks right — use it in DONJON." Cost: three conditional links.

**5. Rebuild /openmc around one journey strip and make its SPH plan complete.** Today four numbered systems disagree about what "01" means, and the SPH plan's "copy these in order" list fails at step 2 because the sidecar-building commands live elsewhere with only a collapsed panel as a bridge. Change: nav href drops `equivalence=sph`; Main line absorbs the demo card (its three prefilled deep links become per-phase actions — they are the only path that auto-loads the physics summary, so they must survive); delete the Workflow pipeline strip and the numbered steps grid; splice the three prerequisite sidecar commands into the plan when the sidecar readiness check fails, and link the failed row plus the sidecar field to `/equivalence?kind=openmc-sph-sidecar`; fix the status vocabulary at its source (`passed`→`planned`, `running`→`planning`, header `READY`→`PLAN READY`), keeping planned/blocked/optional. Cost: moderate; the deliverable (CLI commands) and crown jewel (SPH evidence) surface two panels sooner.

**6. Fix /equivalence's three self-inflicted traps.** Make→inject: seed `sphSource`/`adfSource` from the make tab's output on tab switch (~15 lines — the page's whole pairing currently forces hand-copying a path configured thirty seconds earlier). Naming: one convention end-to-end, `openmc_sph.*` (it is what the apply-sph spec already defaults to; `sph_sidecar.h5` collides with a different command), applied to canned CLIs, placeholders, and catalog strings, frozen with parity tests rather than a generator. Form shape: fold only Previous SPH + Damping behind an "Iterative update (review path)" disclosure and group the seven one-shot policy fields under a plain subheading — the rate-target and zero-flux controls are validated production prescription, not expert clutter, and must stay visible. Suppress the workflow panel's canned Copy-CLI on the active step so exactly one copyable version of the command being built is on screen.

**7. Strip the reference chrome on /commands and /builder.** /commands' first screen tells an evaluator "23 PARTIAL" and to leave, three times, before the first command card at four viewports down. Change: delete StatusCounts (one "Open converter" button in its slot), TaskLauncher, and the amber notice; keep the goal guide as screen 1 and the Workflow map as the single orientation device; one visible one-line status legend; rename the "Partial" filter to "Builder". Detail page: merge Use-when/Produces/Next-step + web mapping into one guidance block, delete Tags/bridge/goal-card re-renders, compress workflow position to a breadcrumb. /builder: delete CommandContextPanel (one compact "Produces: … · Next: …" line instead), the WorkflowHint strip, and the bundle 3-card strip (keep the prefill panel — it is the J5 hand-rail); mount the generic Before/After lane strip so the ADF chain gets 1-click hops without cloning the SPH showcase panel. Cost: deletion.

**8. Disclose mock mode symmetrically.** /convert — the page evaluators demo first — reports a fixture write as "created and confirmed on disk" while /pygan interleaves real environment data unlabeled. Change: a persistent "mock" nav chip when /health reports mock, a "mock fixture" stamp on the convert outcome badge (the pattern /pygan's result already uses), and mode-aware write copy. ## 4. Terminology normalizations worth doing

Adopt a shared vocabulary (a `lib/vocabulary.ts` or review grep). The domain terms (MGXS, CE/MG, SPH/NSPH, ADF/DF, L_MULTICOMPO, LCM, Legendre, statepoint) are already correct — the drift is entirely in the app's own coinages.

1. **handoff** = the MGXS HDF5 given to the converter, only. "ASCII handoff" → "ASCII output"/"DONJON ASCII"; "Bundle handoff" → "Bundle"; keep "HDF5 handoff" on /inspect, whose job is deciding whether the file *is* one.
2. **Three-term sequence system:** *workflow* = any ordered command sequence (matches the CLI noun); *route* = a mutually exclusive physics/consumption branch (keep "MACROLIB NSPH route", "OpenMC-side SPH route" — these are the validated credential); *path* = filesystem only ("Handoff path after this result" → "Next steps"). Drop lane/pipeline/chain/line as headings.
3. **augment / apply / never "corrected" for files:** tabs "Inject ADF/SPH" → "Augment ADF/SPH"; the augmented file is "SPH-augmented", apply-sph output is "SPH-applied"; keep "corrected" only for flux physics statements. One lock sentence on /equivalence: "Augment attaches factors as records — cross sections unchanged; apply-sph rewrites the cross sections."
4. **One label per flag, flag shown:** "Preflight (--check)" and "Production checks (--production)" on both /convert and /openmc; retire "gates" and "Validate first". Reserve "production" for the flag; the credential vocabulary is "Accepted validation" ("Live production minicase" → "Live minicase (validated reference)").
5. **bundle** = the one noun for the manifest-backed directory (verb: package); kill "delivery record", "managed handoff bundle", and friends; gloss once per page.
6. **Nav = stem of H1:** "Review HDF5" → "Inspect HDF5"; "PyGan option" → "PyGan validation"; retire the "planner" self-name outliers on /openmc; /equivalence H1 → "ADF/SPH equivalence sidecars".
7. **Jargon:** define "sidecar" once ("a small companion HDF5 carrying ADF/DF or SPH factors"); "smoke" → "smoke test" on first use; "for plumbing" → "for wiring checks only (no physics)"; "file-status probe" → "file check"; /openmc equivalence option "Direct" → "None (direct XS)".
8. **Micro:** "dry run" as noun, "dry-run" as modifier only (keep each panel's distinct second clause — do not merge the sentences); sentence-case the "Use when / Produces / Next step" trio; field label "Input HDF5" → "MGXS HDF5" on /convert.

## 5. Genuinely good — do not touch

- **The J1 spine:** path → auto-derived output → Dry run → Convert → auto-rendered preview → prefilled /donjon → copy deck. One typed path, ~6 clicks, zero forced decisions. Every change above is subtraction around it; none may add a step.
- **The honesty apparatus, verbatim:** the hero's "it does not solve reactor physics"; the SPH summary's "What it does not prove" and `applied_to_xs` footnote; the equivalence page's "factors are physics inputs… it does not judge whether the sidecar values are physically appropriate"; /donjon's "This page does not run DONJON"; the NSPH/MACROLIB consumption caveat everywhere it appears.
- **Accepted validation** on the home page — the exact evidence density this audience trusts, and the only place it lives.
- **The /donjon substance:** the state-aware checklist with the 72-char SEQ_ASCII and hex-VOID-only scars, the ingest-smoke-before-solve ordering, the deep-link parameter set and "Copy page link", and the page's own manifest probe with `donjon_defaults` auto-fill (a named fixed point — the convert-side duplicate probe is the cut, never this one).
- **Verification substance on /convert and /inspect:** the Production evidence strip, CheckCards gate details, full issue/warning lists, the cross-section plot, the scatter heatmap with moment refetch and its keep-last-good error recovery, the handoff signature + block scan.
- **The trust mechanics:** the file-status probe and its conflict state; CLI previews that provably match web runs (the unit-tested pygan parity pattern — extend it, don't replace it); argparse-dependency warnings; the "Preselected in web / You still provide" mapping on command detail pages; per-target extension filtering in the shared FileBrowserModal.
- **The demo card's inline-status pattern** on /convert — it is the model the rest of the report should imitate.
- **Every field-to-flag mapping** on /equivalence and /builder: nothing speculative survived inspection; the hint copy ("identity keeps previous SPH where both CE and MG flux are exactly zero") is expert writing worth protecting.

**Net effect if adopted:** same ten routes, same validated substance stated exactly once, roughly half the report surface and one screenful of chrome per secondary page removed, all six jobs reachable at their true rank, and the nav finally reads as the pipeline the hero describes: prep → convert → inspect → DONJON. That is 干干净净 applied to the map and the pages — without spending an ounce of the product's credibility.
